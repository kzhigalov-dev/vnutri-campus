# внутри. — навигатор СПбГУПТД

Вознесенский, 44–46: общая 3D-схема пяти этажей, поиск, учебные маршруты и бесплатное бронирование мест. Интерфейс — HTML,CSS и ванильный JavaScript; Three.js и шрифты поставляются локально.

## Запуск

Нужны Node.js22.13+ и npm для полного режима с подготовленным сервером:

```sh
npm ci
npm run dev -- --port 4173 --hostname 127.0.0.1
```

Открыть http://127.0.0.1:4173/index.html. Без ключей доступен учебный режим: записи сохраняются только в этом браузере.

Для сдачи статической части задания без npm/сборки/сервера API:

```sh
python3 -m http.server 8000 --directory public
```

Открыть http://localhost:8000/index.html. Карта, поиск, учебные маршруты, локальная бронь, образец письма и отмена работают без API.

## Что работает

Визуальный стиль — светлый архитектурный атлас: сиреневая поверхность, цветные торцы этажей, контрастные стены и коралловые зоны работы. Оригинальная геометрия и источники сохранены.

- Общая 3D-схема пяти этажей, отдельный ракурс каждого этажа, вращение, масштабирование и плавное переключение. Прогулка от первого лица убрана из интерфейса.
- 149 помещений с индексами модели. Поиск, тип работы и наличие свободных мест синхронно обновляют список и схему. Выбор через карту или кнопки списка.
- Учебные маршруты между этажами: проверяемые проходы, лестничные связи, линия на общей модели, текстовые шаги и переключение этажей. Ссылка сохраняет начало и конец маршрута после обновления страницы. Если связного прохода нет, маршрут не выдумывается.
- Восемь условных зон на четвёртом этаже по восемь мест. Свободные, выбранные и занятые места имеют разные подписи и оформление. Занятые места недоступны для брони.
- Дата — сегодня и 14 дней вперёд по Москве, начало 09–20, 1–4 часа, конец до 21. Все места бесплатны. Проверки пустого выбора, неверных значений и пересечений.
- Сохранение и восстановление брони, уникальный номер, отмена и освобождение мест, синхронизация вкладок. Старые записи совместимы с новым отображением.
- Образец письма с отменой; переход по ссылке сам по себе бронь не отменяет. Настоящих серверных отправок Resend нет.
- Форма отправки данных и обратной связи на клиенте через **EmailJS** (`emailjs.send`): модальное окно для вопросов по аудиториям, заявок и замечаний к схеме, предзаполнение номера помещения из карточки, валидация полей, сохранение ключей в браузере и возможность отправки подтверждения бронирования на Email. Поддерживается интеграция с Яндекс Почтой по SMTP.
- Мобильная версия, кнопки списка и места доступны с клавиатуры. При отказе графики остаются список, бронирование и текстовые шаги.
- Этажи 3 и 4 перестроены по фотографиям навигационных панелей ГУПТД 2026 года: подписи комнат — современная нумерация аудиторий. 17 записей справочника привязаны к своим комнатам на 4-м этаже точно; записи, которых нет на панели (400, 446, 467, 469, 475), не перенесены. Исходные листы и панели доступны на странице источников.

## Что ещё не подключено

Почтового домена и сервиса пока нет: **настоящие письма не отправляются**, серверное создание брони отключено. Сейчас работает явно обозначенная локальная демонстрация. Она не предоставляет права доступа в аудитории.

Для включения пилота позже: подтвердить домен отправителя в Resend и настроить через Sites runtime variables `RESEND_API_KEY`, `MAIL_FROM` (адрес), `SITE_URL` (HTTPS-адрес этого сайта), `BOOKING_TOKEN_SECRET` (случайный секрет минимум32 символа), затем `BOOKING_ENABLED=true`. Секреты не помещать в public/или hosting.json. `.env.example` содержит только имена. Подготовленный сервер использует почту вошедшего аккаунта, не произвольный адрес получателя. Включение настоящего доступа к помещениям требует согласования с университетом.

Миграция D1 находится в drizzle/. Sites применяет её при публикации. Для локальной базы после сборки:

```sh
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_tan_gambit.sql
```

## Форма отправки данных (EmailJS / Gmail / Яндекс)

На сайт добавлена клиентская форма отправки данных (`public/js/contact-form.js`, `public/js/emailjs-config.js`):
1. **Кнопка в шапке «Обратная связь»** и ссылка в подвале сайта открывают модальную форму отправки данных.
2. **Кнопка «Связаться» в карточке любого кабинета** автоматически предзаполняет выбранное помещение и тему обращения.
3. **Отправка деталей брони на Email**: после сохранения учебной брони в карточке появляется поле для отправки подтверждения на личную почту через EmailJS.

### Пошаговая инструкция по настройке EmailJS с Gmail (самый быстрый и удобный способ):

1. **Регистрация в EmailJS**:
   - Зарегистрируйтесь на сайте [emailjs.com](https://www.emailjs.com/) (бесплатный тариф: до 200 писем в месяц).
2. **Подключение Gmail в 1 клик через Google OAuth (Email Services)**:
   - В панели EmailJS перейдите в раздел **Email Services** → нажмите **Add New Service**.
   - Выберите **Gmail**.
   - Нажмите синюю кнопку **Connect Account**.
   - Войдите в свой Google-аккаунт и разрешите EmailJS отправку писем от вашего имени (*«Отправка сообщений электронной почты от вашего имени»*).
   - Нажмите **Create Service** и скопируйте полученный **Service ID** (например, `service_gmail` или `service_xxxxxxx`).
3. **Создание шаблона (Email Templates)**:
   - Перейдите в раздел **Email Templates** → **Create New Template**.
   - Тема письма (Subject): `Новое обращение: {{subject}} (СПбГУПТД)`.
   - Текст письма:
     ```text
     Поступило новое сообщение с карты кампуса СПбГУПТД:
     Имя: {{name}}
     Email: {{email}}
     Тема: {{subject}}
     Аудитория: {{room}}
     
     Сообщение:
     {{message}}
     
     Дата отправки: {{date}}
     ```
   - В настройках шаблона (вкладка Settings):
     - В поле **To Email** укажите ваш Gmail адрес.
     - В поле **Reply-To** укажите `{{email}}` (чтобы при ответе в Gmail ответ уходил автору обращения).
   - Нажмите **Save** и скопируйте **Template ID** (например, `template_xxxxxxx`).
4. **Получение Public Key**:
   - В EmailJS откройте вкладку **Account** и скопируйте ваш **Public Key** (ранее назывался User ID).
5. **Ввод ключей**:
   - Ключи прописываются в файле `public/js/emailjs-config.js` в объекте `DEFAULT_EMAILJS_CONFIG` (`serviceId`, `templateId`, `publicKey`).

### Альтернативно: настройка EmailJS с Яндекс Почтой:

1. **Регистрация в EmailJS**:
   - Зарегистрируйтесь на сайте [emailjs.com](https://www.emailjs.com/) (бесплатный тариф: до 200 писем в месяц).
2. **Разрешение SMTP-подключения в Яндекс Почте**:
   - Откройте веб-версию Яндекс Почты → **Все настройки** (шестерёнка в правом верхнем углу) → **Почтовые программы** → отметьте галочкой пункт **«С сервера по протоколу IMAP/SMTP»**.
   - Откройте [Яндекс ID: Безопасность](https://id.yandex.ru/security) → блок **«Пароли приложений»** → нажмите **«Создать пароль приложения»** → тип **«Почта»** → введите имя (например, `EmailJS`) → скопируйте сгенерированный 16-значный пароль приложения.
3. **Подключение сервиса (Email Services)**:
   - В панели EmailJS перейдите в раздел **Email Services** → нажмите **Add New Service** → выберите **Yandex** (либо Custom SMTP: хост `smtp.yandex.ru`, порт 465 SSL).
   - В поле Email укажите ваш ящик Яндекса, а в поле Password вставьте созданный **пароль приложения**.
   - Сохраните сервис и скопируйте полученный **Service ID** (например, `service_yandex`).
4. **Создание шаблона (Email Templates)**:
   - Перейдите в раздел **Email Templates** → **Create New Template**.
   - Тема письма (Subject): `Новое обращение: {{subject}} (СПбГУПТД)`.
   - Текст письма:
     ```text
     Поступило новое сообщение с карты кампуса СПбГУПТД:
     Имя: {{name}}
     Email: {{email}}
     Тема: {{subject}}
     Аудитория: {{room}}
     
     Сообщение:
     {{message}}
     
     Дата отправки: {{date}}
     ```
   - В поле **Reply-To** укажите `{{email}}`.
   - Нажмите **Save** и скопируйте **Template ID** (например, `template_contact`).
5. **Получение Public Key**:
   - В EmailJS откройте вкладку **Account** и скопируйте ваш **Public Key** (ранее назывался User ID).
6. **Применение ключей**:
   - В файле `public/js/emailjs-config.js` укажите эти значения в объекте `DEFAULT_EMAILJS_CONFIG`.

## Достоверность

Назначения аудиторий 452, 459, 462, 466, 484 подтверждены [программой2025года](https://sutd.ru/sveden/oop/09.02.13-co.pdf). Восемь зон остаются учебными сценариями. Пять из них условно сопоставлены с номерами справочника, три остаются авторскими пространствами. Восемь мест и свободный доступ — учебный сценарий. Примерная занятость:12–15 места2,6, а в читальной зоне все места. В серверном режиме этой демонстрационной занятости нет.

Этажи 1, 2 и 5 перенесены с [архивных чертежей2012года](https://saintcapybaras.com/Home/GetStateExamination/11435?page=102), страницы319–323 экспертизы2023года; их подписи — условные индексы архивной модели (П1.01 и подобные). Этажи 3 и 4 авторски перестроены по фотографиям навигационных панелей ГУПТД2026года: подписи комнат — современная нумерация аудиторий, лестничные башни досованы по положению сохранённых лестничных ядер БТИ для связи этажей. 17 номеров справочника на четвёртом этаже привязаны к совпадающим комнатам панели. Где источник не подтверждает этаж, это прямо указано. Исторические и противоречивые записи сохраняют свои статусы. Маршруты показывают проходы этой реконструкции, не подтверждённые маршруты по нынешнему зданию. Архивный JSON и сканы сохранены. Навигационная схема использует границы выделенных зон и условные дверные проёмы; регистрация этажей по внешним контурам компенсирует разную обрезку сканов. Лестничные связи — условные совпадения соседних этажей, а не подтверждённые натурные переходы. это не проверенное состояние2026года. Высоты, фасад, свет и мебель условные; не использовать для эвакуации.

[Дополнительный поиск актуальных схем](research/voznesensky-44-46/current-plan-search-2026-10-29.md) не дал читаемого плана с современной нумерацией. [Концепция модернизации университета](https://sutd.ru/novosti_i_obyavleniya/announces/24689/) уже включает навигацию и бронирование; работа развивает пользовательский сценарий, не претендует на первенство идеи.
