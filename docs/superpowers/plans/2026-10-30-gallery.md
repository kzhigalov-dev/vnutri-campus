# Campus gallery implementation plan
> Use superpowers:executing-plans inline; user requests autonomous design and implementation.
**Goal:** readable, visually memorable design-school interiors and a coherent polished site.
**Architecture:** pure gallery-layout prepares simplified walls and open door cuts; gallery-scene owns local textures/decor/optional assets; floor-scene uses prepared layout for both rendering and collision. Archive retained. Existing UI/controller untouched except specific labels/help and visual styling.
**Tech:** Vanilla JS, Three0.180, CanvasTexture, local assets, Node tests, Sites.
**Spec:** docs/superpowers/specs/2026-10-30-gallery-design.md
## Constraints
No guessed contemporary room IDs. Decorative setting explicitly illustrative. Same private Site, free booking, no mail configuration changes. Mobile/reduced-motion/lifecycle retained.
## Review focus
Doors cut every overlapping wall segment; decorative meshes must not intercept floor navigation or conceal door openings. Async props cannot attach to stale/disposed floor. Source floor hashes retained. No unusable/unreadable phone chrome. Shared textures not disposed while in use.
## Tasks
- [x] Pure prepared layout and tests: cleanup, internal door placement/cuts, finite in-bound coordinates, source immutable, collision passage.
- [x] Gallery scene: textured floors/wainscot, doors with signs, color wayfinding, posters/cases/lighting; integrate same wall plan with navigation. Inspect eye-level views.
- [x] Asset audit/integration, exterior details; lightweight and guarded loading/disposal.
- [x] Supporting pages final styling/copy; verify booking regression and responsive flow.
- [x] Browser desktop/mobile, tests/tsc/build, fresh review, fix, package and publish existing Site.
